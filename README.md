# cbox

A hardened container runtime for AI coding agents - Claude Code, Hermes, and
Codex behind one enforced boundary, with one shared on-disk memory that survives
session limits and machine switches.

Coding agents are not really usable unattended on their own: either they stop to
ask for approval every few steps, or you switch the checks off and hand them your
machine. cbox removes that trade-off by moving trust from the agent to the
boundary. Any agent runs at full autonomy inside a locked-down container -
network-gated, filesystem-scoped, host untouched - and every engine reads the
same per-project brain, so work continues across session ends, usage limits, and
even across engines. When you need a second opinion, agents delegate to each
other - depth-limited, git-scoped, fully audited.

## Why cbox

- **Agent-agnostic by design.** The boundary, the shared memory, and the guards
  belong to cbox, not to any vendor. Claude Code, Hermes, and Codex run as
  interchangeable engines; local models plug in as another tier. Switching or
  mixing engines costs nothing.
- **Any agent, sandboxed and unattended.** Run an agent with full autonomy and
  no approval prompts inside a locked-down container - the container *is* the
  boundary, so the host stays safe even if the agent is hijacked. Policies are
  mounted read-only, and SSH private keys never enter the container (only a
  signing socket is forwarded).
- **One shared brain and session index across engines.** `LEDGER.md + PROGRESS.md`
  and `.cbox/sessions/` per project persist across session ends and usage limits.
  Any engine reads the same memory on start and continues where the last one
  stopped - no re-briefing.
- **Cross-engine delegation.** Engines delegate work to each other over the
  shared brain. Every call is depth-limited, restricted to an in-scope git
  worktree, and written to a bytewise audit log.
- **Model routing to cut cost.** Route routine work to cheaper tiers and reserve
  the frontier model for the hard parts. Optional local model (Ollama, Qwen) as
  a zero-cost worker, off by default.
- **Session auto-resume.** A watchdog detects usage limits and resumes the task
  from the shared brain (optional).

## Quick start

```bash
cbox setup          # one-time wizard, stages all setup
```

Open a new shell (or `source ~/.bashrc`) after setup so the shortcuts load, then,
from a project folder:

```bash
claude                             # start Claude Code
codex                              # start Codex
cbox ai analyse claude             # read-only scan
cbox ai plan claude -p "task"      # plan only
cbox ai full claude -p "task"      # execute the task, unattended
```

The `cbox`, `claude`, `codex`, and `hermes` shortcuts are optional bash functions
generated by setup (`hermes` only when the hermes engine is enabled). If they are
not on your PATH - for example if you skipped the shell-functions step - call the
tool by its full path: any `<shortcut>` is just `/path/to/cbox run <shortcut>`
(e.g. `/path/to/cbox run claude`), and a bare `/path/to/cbox` opens the hub.

`cbox ai` takes a mode (`analyse|plan|full`), an engine (`claude|codex|local-qwen|auto`),
and an optional prompt. All binaries, settings, and policies are pre-configured.
Every delegated call passes an audited guard: an in-scope git worktree, one
delegation hop, and full bytewise logs.

Run a bare `cbox` in a project to open an interactive hub - pick an engine to start
or attach, resume a session, or reach `shell`, `logs`, and `doctor` for the current
project. See [MANUAL.md](MANUAL.md) for details.

## Modes

- **global** (default): one container shared across all workspaces.
- **isolated**: one container per project.

See [MANUAL.md](MANUAL.md) for the setup wizard, storage modes (mount vs volume),
lifecycle, cross-engine delegation, troubleshooting, and per-feature toggles.

## Security

Every agent runs inside the container boundary, so unattended, full-access
execution never touches the host beyond what you explicitly mount. Guards enforce
git-scope on every delegated call, cap delegation depth, and write bytewise audit
logs. Network access is gated by an optional domain-allowlist egress proxy, and
no secrets are baked into the image.

## Roadmap

The goal: an agent that works as if it ran natively on your machine, without you
having to trust it - what it may touch, which external connections it may open,
and a full record of what it executed where all stay under your control. The
near-term work, roughly in order:

- **Reach the host through the egress path.** Connect from the sandbox to
  anything on the laptop - additional workspaces, SSH machines, local services -
  as if running natively, with every connection explicitly allowlisted and
  logged. Builds on the existing egress proxy, host-route, and netaccess
  plumbing, all off by default today.
- **Local models as a first-class zero-cost tier.** Land the Ollama-backed local
  engine as a running everyday option (the wiring exists, off by default).
- **A machine mesh over WireGuard.** Finish the WireGuard network: machines
  connected to each other, remote endpoints reachable over the tunnel, and
  cross-machine session shadowing - watch or take over a session running on
  another box.
